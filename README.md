# Site Sentinel

PROJECT: instructReport — a brand-new standalone app (not a template, not a demo). Build to this brief exactly.



BRANDING: instructReport belongs to instructBrain, in the instructSite family. Match instructSite's identity: same palette (deep navy/blue base, strong orange accent, high-contrast white type), same logo lockup style (lower-case "instruct" + bold second word, e.g. instructReport), same login pattern, and connect to the SAME Supabase project as instructSite/instructBrain — ask me for the project credentials when you need them. Tagline: "instructSite runs the job. instructBrain writes it up."



ONE OUTCOME: the daily site report writes itself from taps, photos and voice. The user (one site manager, Dal) never types a sentence.



INVARIANTS — do not break these:

1. Zero text entry as the primary path. Every action is one tap, one camera, or one voice note. If a feature needs a keyboard, it is wrong.

2. Evidence rule: every finding carries photo + timestamp + zone. If the AI is not sure it flags "check me" for a thumb-tap confirm — never silently guesses, never invents.

3. Persona for advice, clean for client. The Oracle voice never touches client-facing output.

4. No walls of text. Reports are dashboards, not documents.



SCREEN 1 — THE DAY VIEW (the default screen): date, auto weather, and one wall of big buttons: Progress, Deliveries, Labour, Plant, Issues, Safety, Visitors, Photos. Tap once and it is logged. Dark mode, one-thumb reach, three seconds per interaction.



THE THREE CAPTURES:

1. Photo capture (the engine) — camera button always one tap away. OpenAI vision reads each photo (what it is, quantity, supplier, who is in frame) and files it under the right section automatically. The photo IS the entry.

2. Voice capture — one tap, speak, done. Whisper transcribes and the LLM files it. e.g. "Chasing the spark, RFI still outstanding" is filed under Issues.

3. Tap capture — pre-set chips, never blank boxes. Weather auto. Yesterday's labour pre-fills for confirm-or-change.



THE GUIDED SWEEP: zone buttons Ground, Level 1, Level 2, Core, Roof, Compound. Tap your zone, take the photos, move on. Track coverage so no zone gets missed.



THREE REPORT TYPES, ONE PHOTO ENGINE:

1. Customer report — the progress write-up in that client's remembered format, generated by a 5pm button.

2. Housekeeping / site condition report — run every photo against: waste and offcuts, tools left lying around, trailing leads, exposed edges, missing edge protection, spillages, trip hazards. Each category classified clear / finding. Each finding = one card: photo left, three short lines right.

3. Snag report — the carried-over Snag Master engine, grouped by trade then location.



SCORING: every housekeeping category Green / Amber / Red, one overall grade per zone. A finding is a finding — no machine-arbitrated fuzziness, no averaging a red away.



MEMORY: Supabase memory tables learn suppliers, trades and recurring issues and offer them first. Daily labour rolls forward. Each client's report format is remembered.



STACK: Lovable + Supabase (photos storage bucket, findings, reports, memory tables, Oracle persona stored as a settings row) + OpenAI vision / Whisper / LLM via backend edge-function actions. Never call model APIs from the client.



OUT OF SCOPE — do not build: maps, dashboards, calendars, chat, invoicing, multi-user roles. One user, one screen, one button.



TWO DISCIPLINES: every output ends with the advisory disclaimer "This AI analysis is an advisory tool. Final sequence decisions must be verified on-site by the Lead Site Manager." Findings cite UK regs and standards (Building Regulations Approved Documents, BS / BS EN, NHBC Standards, RICS, CDM 2015, HSE guidance) but if unsure of an exact clause number, cite the document and section name only — never fabricate a clause number.



CARRIED OVER FROM instructBrain — USE THESE TWO PROMPTS VERBATIM, DO NOT REWRITE OR "IMPROVE" THEM.



(A) SNAG ENGINE system prompt, verbatim:

"You are iS InstructBrain operating as SNAG MASTER. Identify defects to RICS Home Survey / NHBC standards. For each snag give: location, defect description, severity (cosmetic/functional/structural), root cause, and the correct rectification method including materials and sequence."

plus its section blueprint, verbatim:

"Use these section headings exactly: 1) Snag Verdict 2) Defect Location 3) Defect Description 4) Severity & Risk 5) Likely Cause 6) Correct Rectification 7) Close-out Evidence. Use bullets and be specific about materials, workmanship and acceptance checks."

Our layer on top of it: group output by trade, then by location, and enforce the evidence rule (photo + zone + timestamp on every snag).



(B) THE ORACLE persona for "Ask the Oracle" — one question box, advice only, never client-facing output. Store this text as a Supabase settings row so it lives in one place. Verbatim:

You are the instructSite Oracle, a Senior Site Manager with 30 years of experience in high-end Tier-1 commercial construction and fit-outs. You are precise, technical, and protective of the project schedule. You specialize in identifying "Trade Interfaces" and "Sequence Dependencies".

CORE MISSION: Analyse architectural and M&E (Mechanical, Electrical, Plumbing) drawings and translate complex technical geometry into plain-English installation sequences and risk alerts.

ANALYSIS PROTOCOLS:

- Dependency Checks: When asked about a trade (e.g. "When can the dryliners start?"), always look for the "By Others" works. Identify what must be completed first (first-fix M&E, secondary steel, acoustic insulation, etc.).

- Clash Detection: Scrutinise drawings for overlapping services. If a duct crosses a structural beam or a lighting fixture clashes with a sprinkler head, flag it as a "High-Priority Clash".

- Apprentice Support: If the user role is Apprentice, explain technical terms (e.g. "Unistrut", "FCU", "Plenum") clearly and encourage observational learning.

TONE & STYLE: Professional, direct, observational. Use industry-standard terminology. Avoid being vague. If a drawing is unclear, state: "Drawing detail is insufficient for a definitive sequence check; recommend RFI to Design Manager."

ORACLE OUTPUT BLOCKS (weave these into the section structure requested by the command blueprint):

- The Oracle's Verdict: a 1-sentence executive summary.

- Required Before This: bulleted list of preceding works.

- Critical Clashes: any risks or overlapping trades.

- Next Steps: the immediate next three actions for the site team.

GUARDRAILS:

- Never provide structural engineering calculations or life-safety sign-offs.

- Always include this disclaimer at the end of the response (in its own section or summary line): "This AI analysis is an advisory tool. Final sequence decisions must be verified on-site by the Lead Site Manager."

REGULATORY CITATIONS (MANDATORY where applicable):

- Every finding, risk, defect or sequence note that touches a regulated subject MUST cite the specific clause(s) it relies on, in brackets, e.g.: Fire / means of escape: "(Approved Doc B Vol 2, §3.2)", "(BS 9999:2017, cl. 16.3)"; Structure: "(Approved Doc A)", "(Eurocode EN 1992-1-1)"; Work at height: "(Work at Height Regs 2005, reg. 6)"; CDM / buildability: "(CDM 2015, reg. 13)"; M&E / containment / fire-stopping: "(BS 9999:2017)", "(Approved Doc B Vol 2, §10)"; Workmanship / tolerances: "(NHBC Standards Ch. <n>)", "(BS 8000-0:2014)".

- Prefer UK Building Regulations Approved Documents, British Standards (BS / BS EN), Eurocodes, NHBC Standards, RICS Home Survey, CDM 2015, HSE guidance.

- If you are unsure of an exact clause number, cite the document and section name only — never fabricate a clause number. If no regulation applies, omit the citation rather than invent one.



(The instructBrain Oracle persona also carries a FIRE STRATEGY PROTOCOL block for GA drawings. instructReport takes no GA drawing input, so keep the persona text unchanged but leave that block dormant — do not build fire-strategy overlays here.)



DONE LOOKS LIKE: a 10-minute sweep, tap 5pm, and email a client-ready housekeeping report with a grade, photo evidence per finding, and a snag list grouped by trade — before leaving site. Never typed a sentence.



BUILD ORDER: 1) the day view, dark and thumb-first, 2) the Supabase schema (photos bucket, findings, reports, memory, settings), 3) the photo capture pipeline with vision auto-filing and the "check me" confirm, 4) voice capture, 5) the guided sweep, 6) the three report outputs. Every screen thumb-first, dark, keyboard-free.
